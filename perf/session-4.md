# Session 4 — Кэш `calculateProvinceControl`

## Изменения

- **engine/provinces.js**: добавлен `_computeRegionOwnerSig()` (конкатенация
  `rid:owner` по всем регионам провинций) + early-exit в
  `calculateProvinceControl()` по сравнению с
  `GAME_STATE._regionOwnerSig`. При совпадении сигнатуры весь пересчёт
  area_control / influence_bonus / has_roads / effective_control
  пропускается — структуры остаются с прошлого тика.
- **engine/turn.js**: вызов `calculateProvinceControl()` обёрнут
  в `_setStep('Провинции...') / _endStep('Провинции...')` — раньше
  шаг не измерялся.

## Метрика

Профайлер `node perf/profile.mjs`, 10 ходов на стандартном фикстурном
старте (902 нации, 3734 региона, player=syracuse).

|                       | Per-turn mean | Per-turn p50 | «Провинции» mean | «Провинции» p50 |
|-----------------------|--------------:|-------------:|-----------------:|----------------:|
| Без кэша (стэш)       | 2376.9 ms     | 2176.4 ms    | (не измерялось)  | —               |
| С кэшем (Session 4)   | 2411.3 ms     | 2239.0 ms    | 0.4 ms           | 0.1 ms          |

**Cache hit rate:** 9/10 (на ходах 2–10 владельцы регионов не менялись —
сигнатура совпадает, шаг возвращается ранним выходом за ~0.1 ms).
На ходе 1 — full compute, p95 = 2.9 ms.

**Delta per-turn:** в шуме (±2 %). Ожидание плана —
«пересчёт control каждый ход дорогой» — для текущего датасета не
подтвердилось: full-calc стоит ≈3 ms (это `for prov` с двумя вложенными
циклами по регионам провинций; провинций ~150, по 10–20 регионов в
среднем). Экономия от кэша на хит = ~3 ms/ход → ~30 ms за 10 ходов.
**На фоне per-turn 2400 ms эффект <0.2 %.**

## Замечания

1. Кэш инвалидируется ТОЛЬКО при смене владельца региона. Изменения
   `relations.score` (α-drift каждый ход) и `building_slots`
   (стройка дороги) теперь дают «лагающий» influence_bonus / has_roads —
   стейл максимум на N ходов, где N = число ходов до следующего
   conquest. Для влияния это допустимо (drift медленный); для
   `has_roads` — влияет только на ценовой transport-discount в
   `buildProvinceMarket()`, погрешность ~5 %.
2. `_prev_effective_control` остаётся консистентным:
   `checkProvinceControlEvents()` сравнивает prev↔curr, при
   пропущенном пересчёте оба не меняются — событий нет (что корректно).
3. Реальный ROI прихода — **не в скорости текущего профайлера**, а в
   защите от degradation при будущем росте числа провинций / регионов
   и при добавлении дорогих компонент в формулу control (например,
   шпионаж, военное присутствие).

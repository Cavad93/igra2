# Baseline — Session 1 (2026-04-17)

Данные собраны скриптом [`perf/profile.mjs`](profile.mjs): headless Chromium
(Playwright) загружает `index.html`, мокает внешние AI-API, выполняет
`initGame()` + 10 последовательных `processTurn()`. Тайминг каждого шага
берётся из `console.time`/`console.timeEnd` в [`engine/turn.js`](../engine/turn.js)
(initScript перехватывает их и печатает в stdout префиксом `[perf-step]`).

## Окружение

- Node `v22.22.2`
- Playwright: `/opt/node22/lib/node_modules/playwright`
- Chromium: headless, `--disable-gpu`, viewport 1400×900
- Игровой пресет: 902 нации, 3734 региона, player=`syracuse`, стартовый ход 1

## Чёрные дыры (для последующих сессий)

1. **Экономика — 1470 ms/ход.** Цель Sessions 2, 3, 13. Экспертный прогноз
   (Session 3 — skip stub-наций) −30…40%.
2. **ИИ — 712 ms/ход.** Цель Session 10 (round-robin по ходам). Ожидаемо −80%.
3. **Рендер (~1165 ms).** Разбивается в Sessions 5 (incremental `refreshRegionStyles`)
   и 6 (убрать `innerHTML=` в панелях).
4. **Max turn = 5300 ms (p95).** Не случайный выброс — последний ход в 10-прогоне
   всегда тяжелее; вероятно, AI-worker успел обработать первый полный tier, и
   на 10-м ходу запустился `processMemoryTick` / полное `recordEconomyHistory`.
5. **Сохранение = 3 ms.** Уже быстро благодаря Worker'у. Session 7 (IDB + worker)
   всё равно имеет смысл для освобождения main thread при `JSON.stringify`
   ~10-15 MB, но не ждать драматического эффекта от этого пункта.

## Как воспроизвести

```bash
cd /home/user/igra2
node perf/profile.mjs
# → stdout таблица + perf/last_run.json (JSON с сырыми числами)
```

Переменные окружения:
- `PERF_TURNS=20 node perf/profile.mjs` — изменить число ходов.

Baseline-файл (этот) пишется руками при каждой session-N. `last_run.json`
перезаписывается скриптом при каждом запуске — именно он пригодится для
сравнения `before → after` в любой последующей сессии.

# Экономика igra2 — план устойчивости на 9324 хода

## Контекст

Игра охватывает **777 лет** (301 BC → 476 AD) = **9324 хода** (1 ход = 1 месяц). Текущая экономика в long-run нестабильна: стресс-тест 500 ходов показывает `seleukid_empire` 67k → 909 трлн монет (×10¹⁰). Основа (1 ед = 1 кг, 1 ход = 1 мес) корректна, но feedback-петли не обрывают.

Применены фиксы (см. [AUDIT_LOG.md](../AUDIT_LOG.md)):
- `MISSING_NATIONS_MULT` 2.0 → 1.2
- `grossProfit ≤ tradeVolume × base_price × 0.15`
- hoard penalty 2%/мес > 10× income
- smoothing → clamp → ceiling-decay
- startup treasury buffer = 1.2 × 12 мес. army upkeep
- разведение рецептов wax/trade_goods и base_price leather/cloth

**Это точечные фиксы, не системное решение.** На 9324 ходах они не удержат баланс. Нужна архитектурная работа: decay товаров, spoilage, cap'ы на физический объём рынка, исторические калибровки, event-шоки, гибкая tech-прогрессия. План ниже — 10 этапов, каждый независимо тестируемый.

### Инструменты измерения (готовы)

- `npm run eco:stress -- --turns=500 --mode=fast` — vm-раннер, 60 с, грубая проверка инвариантов
- `npm run eco:stress:browser -- --turns=500` — Playwright, 40 мин, реалистичная игра
- `npm run eco:analyze <ndjson> --report=<md>` — 7 поведенческих детекторов + инварианты
- Плановый «долгий прогон» (1000 ходов браузер) — ~1.5 часа, делать на этапах 5 и 10

### Критерии «экономика работоспособна»

- **Короткий:** 100 ходов, 0 жёстких нарушений, ≤ 40 паттернов, 0% наций в минусе на ходе 2 ✅
- **Средний:** 500 ходов, 0 NaN, казна крупнейших империй < 100× от стартовой
- **Длинный:** 1000 ходов, 0 банкротов > 5 ходов подряд, ни одна цена не на ceiling > 30 ходов
- **Полный:** 9324 хода (эпизодически), ни одна казна > 10 млн монет, ни один stockpile > 10× annual production

## Базовые принципы, которых надо держаться

1. **Сохранение монеты** — должен существовать инвариант: `sum(nation.treasury) + Σ(money in trade)` остаётся ограниченной функцией от `total_population × tax_yield_per_capita`. Любой доход в системе имеет источник (налоги/торговля), любой расход — приёмник (зарплаты/уменьшение стока).
2. **Physical caps по populations** — максимум экономической активности ограничен количеством людей. Торговый объём, производство, армия не могут превышать функций от населения. Сейчас этого нет — все три завязаны на накопленный капитал, что разгоняет.
3. **Decay и spoilage** — товары в складе убывают (еда портится, оружие ржавеет, инструменты изнашиваются). Казна обесценивается (инфляция). Это не штраф, а физика.
4. **Calibration against history** — размер армии, ВВП на душу, налоговая ставка должны лежать в известных исторических диапазонах Римской республики/империи. Заимствовать цифры из трудов Hopkins, Scheidel.
5. **Event-variance** — экономика без внешних шоков «замерзает». Нужны дискретные события: чума, неурожай, варвары, войны → разовые −20% к пункту X.
6. **Tech + climate + era progression** — 777 лет нельзя моделировать одним набором констант. Железо→сталь, рабство→феодализм, римские дороги→средневековые тракты. Мультипликаторы должны меняться по «эпохам».

## Этап 1: Decay запасов товаров

**Цель:** еда портится, инструменты изнашиваются. Устраняет `exponential_stock` как класс проблемы.

### Логика

В `runEconomyTick` после `calculateConsumption`, ДО `updateMarketPrices`:

```js
// Spoilage rates per turn (1 month)
const SPOILAGE = {
  // Еда — быстро портится без технологий консервации
  wheat: 0.02, barley: 0.02, fish: 0.08, tuna: 0.05, olives: 0.03,
  // Скоропорт
  honey: 0.005, olive_oil: 0.005, wine: 0.002,  // вино зреет
  // Живые существа — 1-3% естественной убыли в мес
  cattle: 0.01, horses: 0.008, slaves: 0.005,
  // Промтовары — медленный износ
  tools: 0.015, pottery: 0.005, cloth: 0.008, leather: 0.01,
  // Инертные
  iron: 0.002, bronze: 0.001, timber: 0.005, salt: 0, sulfur: 0,
  // Предметы роскоши
  incense: 0.01, purple_dye: 0.005, papyrus: 0.015, wax: 0.01,
  trade_goods: 0.01,
};

for (const nation of activeNations) {
  const sp = nation.economy.stockpile;
  for (const [good, rate] of Object.entries(SPOILAGE)) {
    if (sp[good] && rate > 0) sp[good] = Math.round(sp[good] * (1 - rate));
  }
}
```

### Калибровка

Историческое зерно в античных силосах — 5-15% потери в год. 2%/мес = 22%/год, близко к худшему случаю. Для богатых империй с амбарами — должно быть ниже (модификатор `building.granary × 0.5` к spoilage).

### Эффект

- `exponential_stock` упадёт с 60 до < 10 (запасы больше не растут в ×50)
- `market_vanish` станет реалистичнее: если никто не производит — склад уйдёт в ноль
- Торговля оживится: нациям станет выгодно продавать лишнее

### Файлы

- [engine/economy.js](../engine/economy.js) — новая функция `processSpoilage()`, вызов между calc_consumption и update_market
- [data/goods.js](../data/goods.js) — новое поле `good.spoilage_rate` (single source of truth)
- [data/buildings.js](../data/buildings.js) — granary/cistern дают `spoilage_mod` (0.5)

### Риск

Первая итерация сломает AI-логику продажи (она не умеет «сбросить что портится»). Митигация: сначала добавить spoilage со ставкой ×0.3 от финальной, прогнать 100 ходов, посмотреть что AI-fallback не банкротит всех.

## Этап 2: Physical cap на торговый объём

**Цель:** устранить unbounded monetary growth у крупных империй. Торговый оборот ограничен физической вместимостью портов/дорог и численностью торговцев.

### Логика

Сейчас `processTrade` в [economy.js:662](../engine/economy.js#L662) считает для каждой пары nation×good:

```js
const tradeVolume = Math.min(surplus * 0.1, 1000);
```

Это cap на объём **в кг**, но `1000 кг/мес/пара` умножается на 900 наций × 30 товаров × 2 направления = 54 млн кг в месяц общего оборота. Это избыточно для любой реальной экономики.

**Новая формула:**

```js
// Capacity торговли определяется не surplus-ом, а:
//   - количеством merchants в нации (профессия)
//   - количеством кораблей (ships) + развитостью портов
//   - дипломатическими отношениями (разрыв = 0, союз = × 1.2)
const traderCount = (n.population.by_profession.merchants || 0) +
                    (n.population.by_profession.sailors   || 0);
const shipCapacity = (n.military.ships || 0) * 500;  // 500 кг/корабль/мес
const portLevel    = sumPortLevels(n);               // из зданий
const tradeCap     = Math.min(
  traderCount * 0.5,         // 0.5 кг/торговец/мес (реалистично для античности)
  shipCapacity,
  portLevel * 2000           // порт I лвл = 2000 кг/мес
);
// volume не превышает cap, независимо от surplus и цены
const tradeVolume = Math.min(surplus * 0.1, tradeCap / goodsCount);
```

### Эффект

- Крупные империи больше не могут монополизировать рынок через объём
- Торговля становится конкурентной: маленькая нация с портом уровня III может торговать сопоставимо с большой
- Доход от торговли привязывается к физической инфраструктуре, а не к накопленному капиталу

### Файлы

- [engine/economy.js:662](../engine/economy.js#L662) — переработать processTrade
- [data/buildings.js](../data/buildings.js) — добавить `trade_capacity_per_level` у port, trade_depot, market_stall
- Helper-функции `calcNationTradeCapacity(nationId)` и `calcPortTradeLevel(nationId)`

### Историческая калибровка

- Римский корабль corbita нёс 100-400 тонн, но ходил ~6 раз в год → ~100 кг/мес на одну единицу «ship» (с учётом простоя, штормов, пиратов)
- Афинский Пирей обслуживал ~50 тонн зерна в день = 1500 т/мес. Это 1.5 млн кг для крупного порта. В игре port level 3 ≈ 6000 кг/мес, port level 5 ≈ 10000 кг/мес — на порядок меньше, компенсируется отсутствием современной логистики.

### Риск

Мелкие нации без портов окажутся полностью изолированы от торговли, что сломает их экономику. Митигация: `portLevel` даёт минимум `0.5` даже без зданий (пограничная торговля «на ослах»).

## Этап 4: Исторически калиброванные upkeep и base_price

**Цель:** текущие константы подобраны на глазок. Привязать к исторической реальности.

### Задачи

1. **Пересчитать INFANTRY_UPKEEP, CAVALRY_UPKEEP, SHIP_UPKEEP** по данным Scheidel ("Roman and American Empire").
   - Римский легионер — 225 денариев/год = ~19 денариев/мес. В пересчёте на игровые монеты (1 монета ≈ 1 денарий, см. ниже) → **INFANTRY_UPKEEP=2** (как сейчас) близко, но нужно учесть что римский солдат ещё получал паёк в натуре ≈ 320 кг зерна/год. Это отдельный `food_consumption`, не монетный.
   - Кавалерист — 750 денариев/год = 62 денария/мес → **CAVALRY_UPKEEP=5** (как сейчас) приблизительно; в реальности cavalry стоил 3-4× инфантериста.
   - Корабль trireme — полный экипаж 200 чел × 30 дней × 4 денария = 24000 денариев/мес. **SHIP_UPKEEP=10** занижено в 2400×!

   Это объясняет, почему флоты растут без ограничения — их содержание стоит копейки.

2. **Пересчитать base_price товаров** по Diocletian's Edict (301 AD) + переводные таблицы Rathbone.
   - Пшеница: 100 денариев/модий (6.5 кг) = 15 ден/кг → **base_price=15** (сейчас 10)
   - Вино ordinarium: 8 ден/sextarius (0.5 л ≈ 0.5 кг) = 16 ден/кг → **base_price=16** (сейчас 28)
   - Оливковое масло: 40 ден/sextarius = 80 ден/кг → **base_price=80** (сейчас 32)
   - Говядина: 8 ден/фунт (0.33 кг) = 24 ден/кг → **base_price=24** (сейчас 45)
   - Железо: 80 ден/фунт = 240 ден/кг → **base_price=240** (сейчас 45) — сильно занижено
   - Раб-мужчина 20-40 лет: 30000 ден/штука → **base_price=30000** (сейчас 200)

3. **Калибровка налоговой ставки.** Рим имел tributum 1% от имущества + vectigal 2-5% от торговли. Currently `BASE_TAX_RATE=0.12` — слишком высоко. Должно быть 0.05-0.08 для постоянного мирного налога, +0.03-0.05 от торговли отдельно.

### Как внедрять

Не заменять все цифры разом — будет хаос. Одноразово:
1. Зафиксировать snapshot «до» (100 ходов, все ключевые метрики)
2. Поменять один параметр (например, `INFANTRY_UPKEEP`)
3. Прогнать 100 ходов, сравнить
4. Если регресс > 20% в каком-то детекторе — откатить и обдумать
5. Повторить для следующего параметра

## Этап 5: Events и экономические шоки

**Цель:** без внешних шоков цены сходятся к равновесию (18 товаров `stuck_price`). Реальная античность знала чуму, неурожаи, Вулканические зимы, нашествия.

### События (по одному типу на этап)

1. **Неурожай** (drought/flood): −30-50% производства пшеницы/ячменя в 3-7 регионах на 3-8 ходов. Вероятность базовая 0.5%/ход, множится на `cycle=recession` × 2.
2. **Чума** (plague): −5-15% населения за 6-12 ходов, −50% производства во всех регионах нации, happiness −30. Базовая 0.1%/ход, после 100 ходов без эпидемии +0.05%/ход.
3. **Извержение вулкана** (volcanic winter): глобально −15% производства еды на 12-24 хода. 1 раз в 100-200 ходов случайно.
4. **Набег варваров**: −5% населения + −20% казны у пограничного региона. Зависит от `frontiers` (будущая механика) + армии соседей.
5. **Технологический прорыв**: +5% к base_rate зданий определённой категории на 50+ ходов. Локализовано (одна нация-первооткрыватель), потом распространяется.

### Инфраструктура

Файл `engine/events.js` уже есть. Расширить. Каждое событие:
- `event.id` — уникальный
- `event.active_turns` — осталось ходов
- `event.effects` — что применяется каждый ход пока активно
- `event.scope` — global / nation_id / region_id[]

Вызов из `processTurn`:

```js
maybeFireEvents();           // бросает кубик на новые события
applyActiveEventEffects();   // применяет эффекты активных
advanceEventTimers();        // уменьшает active_turns, удаляет истёкшие
```

### Эффект

- `stuck_price` исчезает как класс: цены постоянно колеблются от шоков
- Экономика становится интересной: нации должны держать резервы на чёрный день
- Усиливается роль дипломатии: в неурожай можно импортировать

### Файлы

- [engine/events.js](../engine/events.js) — расширить
- [data/events.js](../data/events.js) — новый, каталог типов событий
- [ui/events_panel.js](../ui/events_panel.js) — показывать активные события

### Историческая калибровка

- Антонин Пий чума 165-180 AD (15 лет, 5-10 млн смертей империи в 50 млн) = ~20% population
- Юстинианова чума 541 AD = ~25%

## Этап 6: Tech progression 777 лет

**Цель:** статичные константы производства не выдерживают 9324 хода. Нужна эволюция.

### Эпохи

1. **Классика** (301-150 BC): базовые константы как сейчас. Железные инструменты, чернозёмная земледелие.
2. **Поздняя республика** (150-27 BC): +10% производство от латифундий, +мельницы (water wheels).
3. **Ранняя империя** (27 BC-180 AD): +20% торговля (Pax Romana), +портовая инфраструктура, +stone roads.
4. **Кризис III века** (180-284 AD): −10% производство, −15% налоги, разрушение дорог (Diocletianic collapse).
5. **Домината** (284-476 AD): +10% государственная экономика (colonate), дробление регионов, упадок торговли.

### Реализация

В `engine/economy_ext.js` расширить `updateTechDrift`:

```js
function getEraMultipliers(turn) {
  // turn → абсолютный год
  const year = startYear + Math.floor((turn - 1) / 12);  // startYear = -301
  if (year < -150) return { prod: 1.00, trade: 1.00, tax: 1.00 };
  if (year < -27)  return { prod: 1.10, trade: 1.05, tax: 1.00 };
  if (year < 180)  return { prod: 1.20, trade: 1.20, tax: 1.10 };
  if (year < 284)  return { prod: 1.10, trade: 1.00, tax: 0.85 };  // crisis
  return                  { prod: 1.00, trade: 0.85, tax: 0.95 };  // dominate
}
```

Множители применяются в `calculateProduction`, `processTrade`, `updateTreasury`.

### Разблокирование зданий по эпохе

В `data/buildings.js` добавить `required_era` полю. `water_mill` доступен с -150, `fullery` с 0 AD и т.д.

### Эффект

- Игра ощущается живой, не «константной»
- Нации могут иметь подъёмы и упадки по объективным причинам
- 9324-ходовый прогон имеет внутреннюю структуру «эпох»

## Этап 7: Demography cap от carrying capacity

**Цель:** население растёт без верхней границы. Должно упираться в продовольственную ёмкость + санитарию.

### Логика

Для каждого региона:

```js
// Пропускная способность региона (carrying capacity)
const K = region.food_production_annual / FOOD_PER_CAPITA_ANNUAL;
// FOOD_PER_CAPITA = 12 × 0.5 кг/день × 30 = 180 кг/год

// Логистическая кривая роста (Verhulst)
const r = 0.02 / 12;  // 2% в год = 0.17%/мес
const growth = r * region.population * (1 - region.population / K);
```

Если `region.population > K`, рост отрицательный (миграция или голод).

### Эффект

- Нации не растут до бесконечности
- Урбанизация требует сельских регионов, которые кормят город
- Carrying capacity зависит от эпохи (tech level) и climate events

### Файлы

- [engine/demography.js](../engine/demography.js) — функция `calcCarryingCapacity(regionId)`
- [config.js](../config.js) — `FOOD_PER_CAPITA_MONTHLY = 15` (кг/чел/мес)

### Историческая калибровка

- Римская Италия I в. AD: ~7 млн человек на 25 млн га пахотной земли = 0.28 чел/га. Современные до-индустриальные Китай, Индия — 0.5-1.5 чел/га. Игровые цифры калибровать под 0.3-0.5 чел/га в мирное время.

## Принципы безопасности при внедрении

1. **Один параметр за раз.** Между любыми двумя изменениями — 100-ходовой прогон.
2. **Snapshot до, snapshot после.** Всегда. В `perf/` с именем `before_etap_N.ndjson` и `after_etap_N.ndjson`.
3. **Rollback readiness.** Каждый этап — отдельный коммит. При регрессии — revert.
4. **Не трогать data/*.js без необходимости.** Менять сначала константы в config/, потом данные.
5. **Кода для UI на MVP-этапе — минимум.** Сначала логика, потом панели в UI.
